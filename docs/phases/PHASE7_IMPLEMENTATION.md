## 2. Canonical Verification State Model & Decision Engine

### 2.1 State & Outcome Taxonomy
The verification system enforces strict separation between workflow states and decision outcomes:

- **Workflow State:**
  - `PENDING_REVIEW` (`verification_pending`): Reinspection requested or queued; awaiting transit pass or human audit.
- **Canonical Decision Outcomes:**
  - `RESOLVED`: Target corridor covered, optical quality sufficient, zero residual defect detected. Confirms municipal repair.
  - `UNRESOLVED`: Target corridor covered, but defect remains detected by YOLOv8 model ($\ge 50\%$ confidence). Repair failed or incomplete.
  - `INCONCLUSIVE`: Spatial corridor missed, camera quality degraded/occluded, or conflicting multi-frame evidence observed. Requires follow-up pass.
  - *(Strictly rejected: `PARTIALLY_RESOLVED` is not used, as partial fixes require physical reinspection rather than algorithmic guesswork).*

### 2.2 Decision Rules (`backend/app/services/verification.py`)
Deterministic rule evaluation in `evaluate_verification()`:
1. **Rule 1 (Corridor Coverage Missing):** `coverage_confirmed == False` $\rightarrow$ `INCONCLUSIVE`, Failure Reason: `MISSING_CORRIDOR_COVERAGE`.
2. **Rule 2 (Degraded Optical Quality):** `evidence_quality in ("DEGRADED", "BLURRY", "OCCLUDED", "POOR")` $\rightarrow$ `INCONCLUSIVE`, Failure Reason: `OPTICAL_QUALITY_DEGRADED`.
3. **Rule 3 (Conflicting Observations):** `conflicting_evidence == True` $\rightarrow$ `INCONCLUSIVE`, Failure Reason: `CONFLICTING_EVIDENCE`.
4. **Rule 4 (Residual Defect Detected):** `new_detection` present with confidence $\ge 0.50$ $\rightarrow$ `UNRESOLVED`, Failure Reason: `RESIDUAL_DEFECT_DETECTED`.
5. **Rule 5 (Verified Clean):** Coverage confirmed, quality sufficient, zero defect $\rightarrow$ `RESOLVED`.

## 3. Database Architecture & Schema Enhancements

### 3.1 Migration `0011_verification_engine.py`
Added 10 new columns and indexes to the `verifications` table:
- `verifier` (`VARCHAR(100)`): E.g. `TRANSIT_REINSPECTION`, `OPERATOR_OVERRIDE`, `FIELD_AUDIT`.
- `evidence_source` (`VARCHAR(100)`): E.g. `bus_dashcam`, `operator_upload`, `citizen_report`.
- `inspection_job_id` (`VARCHAR(50)`, FK $\rightarrow$ `inspection_jobs.id`).
- `rationale` (`VARCHAR(1000)`): Explainable natural language reason generated by the decision engine.
- `failure_reason` (`VARCHAR(100)`): Machine-parseable failure code for audit indexing.
- `comparison_metrics` (`JSON`): Telemetry payload capturing `coverage_confirmed`, `evidence_quality`, `before_confidence`, `after_confidence`, `before_extent_pct`, `after_extent_pct`, `model_version`, `camera_id`, `corroboration_count`.
- `is_override` (`BOOLEAN`, default `false`): Flags operator-adjudicated entries.
- `overrides_verification_id` (`VARCHAR(50)`, self-referential FK $\rightarrow$ `verifications.id`): Preserves pointer to the automated pass that was superseded.
- `operator_id` (`VARCHAR(50)`, FK $\rightarrow$ `users.id`): Identity of operator who performed override.
- Indexes created: `ix_verifications_issue_id`, `ix_verifications_ticket_id`, `ix_verifications_result`.

### 3.2 Foreign Key Integrity & Self-Healing
- **Transit Bus Registration:** `_ensure_reinspect_bus_exists()` auto-registers previously unseen bus identifiers to prevent FK integrity violations during simulator or ad-hoc runs.
- **Ticket Guarantee:** If a reinspection is processed on an issue that lacks an active work ticket, `process_verification_reinspection()` automatically initializes an associated municipal tracking ticket, ensuring `ticket_id` foreign key constraints are strictly satisfied.
- **Operator Token Handling:** When running under stateless demo admin tokens, `operator_id` cleanly stores `None` while recording `overridden_by` in `comparison_metrics` and timeline logs.

## 4. Defect Recurrence & Spatial Fusion (`ST_DWithin` Geography)

### 4.1 PostGIS Recurrence Matching
- **Function:** `find_nearby_verified_issue(session, lat, lng, detection_type, radius_meters=15.0)` in `backend/app/services/spatial_fusion.py`.
- **Query:** Uses PostGIS spherical geography distance:
  ```sql
  ST_DWithin(
      geography(urban_issues.location),
      geography(ST_SetSRID(ST_MakePoint(lng, lat), 4326)),
      15.0
  )
  ```
- **Filter:** Matches identical defect type (`UrbanIssue.issue_type == detection_type`) on previously resolved issues (`UrbanIssue.status == IssueStatus.verified`).

### 4.2 Reopening Existing Issue & Ticket
When a recurrence match occurs during live or simulated detection ingestion:
- **No Duplicate UrbanIssue:** The existing issue row is reopened (`issue.status = IssueStatus.reopened`).
- **Ticket Reopened:** Linked municipal ticket transitions to `TicketStatus.reopened`.
- **Audit Logging:** An audit `TimelineEvent` (`event_type="defect_recurrence"`) is created.
- **Alert Dispatched:** High-severity alert (`alert_type="defect_recurrence"`) is queued for municipal dispatch.
- **Road Health Updated:** Penalties are immediately recalculated for the parent road corridor.

## 5. Append-Only Operator Override

Manual operator adjudication strictly adheres to immutable audit trail requirements:
- **Prior Record Preserved:** Automated reinspection passes are NEVER updated or deleted in place.
- **Separate Override Entry:** Calling `POST /api/v1/verifications/{id}/override` creates a new `Verification` record with `is_override = True` and `overrides_verification_id = id`.
- **Mandatory Rationale:** Rationale is required and validated; empty submissions return HTTP 422.
- **Auditable Actor:** Operator identity, timestamp, and rationale are recorded in the verification row and an accompanying `TimelineEvent`.
- **Road Health Resynchronization:** Road health burden scores update immediately upon override.

## 8. Truth Audit & Metrics Integrity

| Metric | Permitted Representation | Strict Prohibition |
| :--- | :--- | :--- |
| **Defect Dimensions** | Visible Extent % (`0.0%` to `100.0%` of bounding box) | **NO** fake physical depth (cm) or area ($m^2$) |
| **Model Confidence** | Real YOLOv8 confidence score (`0.0%` to `100.0%`) | **NO** synthetic fallback or hardcoded $99.9\%$ |
| **Corroboration** | Real integer count of distinct transit buses | **NO** simulated multipliers |
| **Corridor Coverage** | Binary `Confirmed` or `Missed` based on spatial tolerance | **NO** assumed resolution without coverage |
| **Timing** | ISO 8601 UTC timestamps from database records | **NO** static mock relative times |
